# Hyprland config

`~/.config/hypr`, owned by this repo since the switch from caelestia's shell to
Noctalia (2026-10-08). It started as caelestia's tree at revision `1ee7a98`;
the untouched original is in `history/caelestia/hypr-reference`, with notes on
what needed caelestia. caelestia is no longer installed (`history/caelestia`).

## Files

Every file is in `manifest.tsv` with its destination under `~/.config/hypr`.

| Repo | What |
|---|---|
| `hyprland.lua` | entry point: loads the modules, then the override layers (below) |
| `variables.lua` | key names, apps, colours read by the modules, with caelestia's defaults; `hypr-vars.lua` overrides values |
| `hyprland/*.lua` | env, general, input, misc, animations, decoration, group, autostart (`execs.lua`), rules, gestures, binds |
| `hypr-vars.lua`, `hypr-user.lua` | the override layers (below) |
| `utils/functions.lua` | helpers the binds and autostart use (pop-up workspaces, picture-in-picture) |
| `animations/` | animation presets, one picked by name in `hyprland/animations.lua` (below) |
| `scheme/default.lua` | fallback colours, copied to `scheme/current.lua` when that is missing |

`hyprland-gui.lua` (HyprMod, `linux/hyprmod`) and `hyprsunset.conf`
(`linux/hyprsunset`) also live in `~/.config/hypr` but belong to those packages.
`scheme/current.lua` (the colour file that borders, group bars and the background read)
is generated by a Noctalia template from the wallpaper palette
(`linux/noctalia`), so it isn't tracked. `scheme/current.conf` is a leftover
caelestia generated; nothing reads it, and `manifest.tsv` lists it as `gone`.

## Override layers

| File | What |
|---|---|
| `hypr-vars.lua` | kitty as terminal, Dolphin as file manager; single-window outer gap matched to HyprMod's `gaps_out`; caelestia's resize keys switched off (see Window mode); Super+C opens VS Code (`code`; caelestia's default `codium` isn't installed); Super+Shift+L runs `systemctl suspend` (caelestia's `suspend-then-hibernate` can't work: zram swap only, so logind reports `CanSuspendThenHibernate=na`); cursor theme `breeze_cursors` (caelestia's `sweet-cursors` isn't installed); volume keys step 1%; the look (window transparency, gradient borders, no shadows, blur behind pop-up workspaces; see Look); `toggles`: Super+D (the communication pop-up workspace) starts and gathers Equibop instead of the official Discord (caelestia kept this list in its `cli.json`) |
| `hypr-user.lua` | Super+Shift+arrow resize binds, HyDE's behaviour defaults (see Look), window mode and per-monitor workspaces (below), and loading `hypr-local.lua` if the machine has one; Hyprland config that HyprMod can't express goes here |

## Load order

`hyprland.lua` loads `hypr-vars.lua`, the `hyprland/*.lua` modules,
`hypr-user.lua` (window mode, per-monitor workspaces), then HyprMod's
`hyprland-gui.lua`, all from `~/.config/hypr`. Until 2026-10-09 the two
override files lived in `~/.config/caelestia`. Later wins, but a duplicate
bind fires twice: overriding a bind from `hyprland/keybinds.lua` needs an
`unbind` first (see `linux/hyprmod`).

## Changes from caelestia's original

- **Autostart** (`hyprland/execs.lua`): starts Noctalia
  (`uwsm app -- noctalia`) instead of `caelestia shell -d`. The gammastep and
  geoclue lines are gone: neither was installed, and the night light is
  hyprsunset.
- **Shell keys** (`hyprland/keybinds.lua`) call `noctalia msg …` instead of
  caelestia's shell. See `linux/noctalia/SETUP.md` for the list. caelestia's
  recording keys, "show all panels", "restart and lock" and "delete clipboard
  entry" have no Noctalia counterpart and are removed. Also removed: the
  ydotool "paste latest" key and the cliphist watchers (Noctalia keeps its own
  clipboard history), the duplicate region-screenshot and colour-picker keys
  (Super+Shift+S and HyprMod's Super+Shift+P stay), Super+P pin (HyprMod's
  Super+Shift+F pins), the test-notification key, and the autostart lines for
  a second gnome-keyring and mpris-proxy.
- **Environment:** uwsm gives apps started by systemd or D-Bus the variables
  in `~/.config/uwsm/env` and `env-hyprland` (`linux/uwsm`), not those in
  `hyprland/env.lua`. Change both when a variable changes.
- **Rules** (`hyprland/rules.lua`): Noctalia's recommended blur for its bar,
  panels and notifications, a floating settings window, and no Hyprland
  animation on any Noctalia layer. caelestia's slide-in for layers otherwise
  made the screenshot overlay drop in from the top. Hyprland matches the whole
  namespace, so the pattern is `^noctalia-.*$`, not `^noctalia-`.
- **Animations** (`hyprland/animations.lua`): picks a preset by name from
  `animations/`. `caelestia.lua` is caelestia's original set and is the one in
  use (quick window open and close, smooth workspace slides, vertical
  slide-fade for pop-up workspaces). The others are HyDE's presets
  (HyDE-Project/HyDE, `Configs/.local/share/hypr/lua/animations/`, GPL-3.0),
  copied unchanged at HyDE commit `fa2fd57a`, with HyDE's GPL-3.0 licence as
  `animations/LICENSE`; they only call `hl.curve` and `hl.animation`, and most
  scale their speeds by `hyde.config.anim.duration_scale`, which the picker sets to 1.
  HyDE's `classic` was tried and dropped: slower window open/close, faster
  workspace switches, sideways pop-ups.

## Look

Settled while ricing on 2026-10-08 against HyDE (HyDE-Project/HyDE and its
themes). Each rule below names the file it lives in.

- **One spacing unit, 4 px**: screen edges, under the bar and above the windows
  all 4 px; 2 px between windows (half the outer gap, Hyprland's own 1:2
  ratio). HyprMod: `gaps_in 1`, `gaps_out 4`; `singleWindowGapsOut 4` in
  `hypr-vars.lua` and window mode's `INSET = 4 + 2` in `hypr-user.lua` follow
  it. The Noctalia bar uses the same unit (`linux/noctalia`, Bar).
- **Shapes**: window rounding 12 (HyprMod), the bar's islands are full pills
  (24 px tall, radius 12). Border 2 px.
- **Borders** (`hypr-vars.lua`): HyDE-style two-colour 45° gradients, focused
  `primary` to `tertiary`, unfocused `onSurfaceVariant` to `outlineVariant` at
  80%, so unfocused windows keep a visible border (caelestia's was almost
  invisible). In Lua a gradient is a table, `{ colors = { … }, angle = 45 }`,
  not HyDE's old text form. Colours come from `scheme/current.lua`, which a
  Noctalia template keeps in step with the wallpaper (`linux/noctalia`).
- **Transparency** (`hypr-vars.lua`, `windowOpacity`): HyDE's 90% focused, 75%
  unfocused, for every window not on HyprMod's opaque list.
- **No shadows** (HyDE). **Blur** stays caelestia's (8, 2 passes); HyDE's 6
  with 3 passes was a close second.
- **Pop-up workspaces** (Super+M, D, S): the workspace behind is dimmed 30% and
  blurred (`dim_special` in `hypr-user.lua`, `blurSpecialWs` in
  `hypr-vars.lua`), as in HyDE.
- **Behaviour** (`hypr-user.lua`, HyDE's `defaults.lua`): apps can't pull
  focus (`focus_on_activate = false`), middle-click pastes, Num Lock on at
  login. Key repeat stays caelestia's 250 ms / 35 per second (HyDE keeps
  Hyprland's slower 600 / 25).
- **Animations**: caelestia's preset (Changes from caelestia's original, above).

## Window mode

Window controls follow one convention: **arrows move, Shift resizes, Alt makes
the step fine**. mpv's image keys use it too (`linux/mpv`).

`hypr-user.lua` defines a Hyprland submap for moving and placing the active
window from the keyboard. It's Lua functions, which HyprMod can't express.
**Super+A** enters it; Esc, Enter or Super+A leave. Other keys do nothing
inside it.

| Key | Floating window | Tiled window |
|---|---|---|
| Arrows | Move 40 px | Move within the layout |
| Alt+arrows | Move 5 px | Move within the layout |
| Shift+arrows | Move an edge 30 px | Resize |
| Alt+Shift+arrows | Move an edge 5 px | Resize |
| Ctrl+arrows | Snap to the left / right / top / bottom half | Nothing |
| `f` | Fill the height | Nothing |
| `c` | Centre | Centre |

Outside the mode, **Super+Shift+arrows** resize the same way, 30 px. The edge
keys move the right or bottom edge in the arrow's direction. When a floating
window sits against the right or bottom side of the usable area (snapped there
with Ctrl+→ or Ctrl+↓), they move the left or top edge instead, so the window
stays against that side.

Floating windows stay inside the usable area of their monitor: the bar (the
monitor's reserved area) and the 4 px outer gap are excluded,
and a step that would cross an edge stops at it. Hyprland resizes a floating
window around its centre, so the edge keys move it by half the change to keep
the other edge put.

caelestia's own resize keys are switched off in `hypr-vars.lua` (empty key
lists): Super+-/=, Super+Shift+-/= and Super+Alt+arrows, which resized by 10%
of the window per press. Those keys are free.

The convention is for these window controls, not every bind. The workspace and
monitor keys keep caelestia's meanings: Shift means "take the window along"
(Super+Shift+1…0, Super+Shift+[ / ]) and Alt means "send it without following"
(Super+Alt+1…0); Super+Shift+arrows is the exception there.

## Per-monitor workspaces

Each monitor has its own workspaces 1–10 on Super+1…0, like awesome/dwm.
[split-monitor-workspaces](https://github.com/zjeffer/split-monitor-workspaces)
does it: a Lua package for Hyprland 0.55 or newer (its rival hyprsplit doesn't
work with Lua configs). It isn't copied into this repo. Install it pinned to the
reviewed commit:

```bash
git clone https://github.com/zjeffer/split-monitor-workspaces.git \
    ~/.local/share/hypr-plugins/split-monitor-workspaces
git -C ~/.local/share/hypr-plugins/split-monitor-workspaces checkout f26d624
```

`hypr-user.lua` requires it by its full name: its modules are called
`globals`, `helpers` and `monitors`, and this config requires its own modules
by bare names too. If the package is missing, the global workspace keys in
`hyprland/keybinds.lua` stay and Super+Shift+N does nothing. HyprMod reads the
whole config by running it and parsing
stdout, so the package's `print()` at setup broke HyprMod (it wouldn't open);
`hypr-user.lua` sends those lines to stderr during setup. Check with
`python3 -c 'import hyprland_config, pathlib; hyprland_config.load_any(pathlib.Path.home() / ".config/hypr/hyprland.lua")'`.

Ranges: main DP-1 gets Hyprland ids 1–10, right HDMI-A-1 11–20, left DP-2
21–30 (`monitor_priority`). A bar that labels workspaces by id (caelestia's
did) shows 11–20 and 21–30 on the side monitors. All 30 workspaces are persistent (the package's
default), so Hyprland's own workspace rules pin each one to its monitor. With
persistence off, every config reload made the package create a missing
workspace on whichever monitor had focus and then move it, and Hyprland handed
the robbed monitor a fallback workspace; on 2026-10-07 that left workspaces and
their windows on the wrong monitor.

| Key | Does |
|---|---|
| Super+1…0 | go to workspace N on the focused monitor |
| Super+Shift+1…0 / Super+Alt+1…0 | move the window there and follow / stay |
| Super+scroll, Super+PgUp/PgDn, Ctrl+Super+←/→ | cycle workspaces on this monitor |
| Super+Alt+scroll, Super+Alt+PgUp/PgDn, Super+Ctrl+Alt+←/→ | move the window to the next/previous workspace on this monitor |
| Super+Ctrl+↓ | first empty workspace on this monitor |
| Super+[ / Super+] | focus the left / right monitor |
| Super+Shift+[ / Super+Shift+] | send the window to the left / right monitor |

caelestia's "groups of 10" (Ctrl+Super+N, Ctrl+Super+scroll,
Ctrl+Super+Alt+N) are unbound. Ctrl+Super+Shift+arrows (move in a direction)
carries a tiled window across monitors at the edge, but a floating window only slides to its own
monitor's edge (Hyprland's floating layout, `moveTargetInDirection`); use
Super+Shift+[ / ] for those.

## Machine-local config

If `~/.config/hypr/hypr-local.lua` exists, `hypr-user.lua` loads it after
everything above. It holds config that stays on one machine and out of this
repo. A load error shows as a Hyprland notification instead of failing quietly.

## Install

Install the packages in `linux/packages.md`, copy every `~/.config/hypr` line
of `manifest.tsv`, install split-monitor-workspaces (above), then run
`hyprctl reload`.

Super+M (the music pop-up workspace) starts Spotify through
`spicetify watch -s`, which refuses to run until Spicetify (a Spotify client
mod) has been applied once, so Super+M does nothing until then. Apply it after
installing, and again after a Spotify update (the package resets the folder to
root-only and drops the patch):

```bash
sudo chmod a+wr /opt/spotify && sudo chmod a+wr /opt/spotify/Apps -R
spicetify backup apply
```

The `chmod` lines are Spicetify's own instructions for Spotify from the AUR.

The wallpapers aren't in this repo; they live in `~/Pictures/Wallpapers` on
the CachyOS desktop.

## Things to know

- `singleWindowGapsOut` in `hypr-vars.lua` must track HyprMod's outer gap by hand.
- Super+R opens the todo pop-up workspace and starts Todoist in it
  (`todoist-appimage`, AUR; see `linux/packages.md`).
